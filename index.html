01Selected work

Cable crane control unit · 7″ display

Main operating screen

Role Interface design, visualisation, control logic

Problem

The operator works outdoors with the machine in motion. They cannot hunt for a value, and they cannot lose sight of the load while opening a menu.

Decision

One number owns the screen — rope force, the value that decides whether the next move is safe. Everything else is peripheral: bars for trends, digits for reference. The menu slides over the screen and closes itself, so machine state is never more than a glance away.

Result

The primary reading stays legible at arm’s length in daylight, and there is no screen the operator can get stuck inside — every path returns home on its own.

Winch controller · fault handling

Alarm manager

Role Fault taxonomy, message system, localisation

Problem

Over two hundred fault conditions across four languages, read by a service technician who may be seeing this machine for the first time.

Decision

Every fault keeps its engineering code next to the plain-language text. The code is what goes into the phone call to the office; the text is what gets the technician moving. Colour carries severity, never information on its own.

Result

Unacknowledged faults pulse, acknowledged ones stay listed but go quiet, and nothing disappears until the condition itself clears.

Diesel engine · Stage V aftertreatment

Emissions escalation

Role State machine, telltale set, operator messaging

Problem

Emissions law dictates the escalation. The operator cares about one thing: how long until the machine stops earning money, and what prevents that.

Decision

Each stage answers the same three questions in the same place — what is wrong, how urgent, what to do. The telltale row never reflows, so a changed icon is noticed by shape and position rather than by reading.

Result

One consistent frame from advisory to derate. The operator learns the layout once and reads state changes at a glance.

02Approach

These are not phones. The hardware is fixed, often years old, and it will outlive several redesigns. That is the interesting part — the constraints are real, and they do most of the arguing for you.

01

One question per screen

An operator arrives at a screen with a question. If the screen answers two, it answers neither quickly. Secondary values stay — but they stay small.

02

Colour is severity, never data

Green, amber and red mean exactly one thing each, on every screen. Anything colour says is also said by shape, position or text — sunlight and colour-blindness both take colour away.

03

No dead ends

Every screen returns home by itself. Menus time out, dialogs default to the safe answer. Nobody should have to power-cycle a machine to leave a submenu.

04

Built for gloves

Touch targets sized for a gloved thumb on a machine that is vibrating. Fewer, larger controls beat a dense grid every time.

03The system underneath

The screens share one vocabulary, so a new page costs a day instead of a week — and an operator moving between machines is never re-learning.
